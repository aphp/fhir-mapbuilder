# Narrow hand-rolled interfaces for MapBuilderBackend's injected dependencies

MapBuilderBackend needs an HTTP client and a process launcher injected so it's testable without a real Matchbox process or the `vscode` module. We considered injecting the library types directly (`AxiosInstance` from axios, `ChildProcess` from `node:child_process`) versus narrow hand-rolled interfaces (`HttpClient` with just `get()`, `ProcessLauncher`/`ProcessHandle` with just `spawn()` and four event callbacks). We chose the narrow interfaces: only `.get()` is ever called on axios today, and `ChildProcess` exposes far more than the four events MapBuilderBackend consumes. A test fake for the narrow interfaces is one small object; a fake satisfying the full library type is a large, brittle mock of code paths never exercised. The cost: production adapters wrapping the real libraries have to be written and kept in sync with `HttpClient`/`ProcessLauncher` as MapBuilderBackend's needs evolve.
